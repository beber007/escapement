# Émulation RP2040 (Raspberry Pi Pico)

Les modèles RP2040 ne viennent pas de Renode mais du dépôt communautaire
[`matgla/Renode_RP2040`](https://github.com/matgla/Renode_RP2040), qui modélise
le timer et ses quatre alarmes, les horloges (PLL, XOSC, ROSC), le GPIO, l'UART,
les deux cœurs, le SIO et le PIO.

## Ça ne fonctionne pas sur macOS arm64

Le dépôt est épinglé sur **Renode 1.16.1**, et ses modèles doivent être compilés
contre les assemblies de Renode. Or le paquet `osx-arm64-portable` est un binaire
**auto-contenu** : il n'expose aucune DLL référençable. Le mode « compilation
depuis les sources » échoue de son côté à la création de la plateforme, juste
après l'initialisation du ROSC — un constructeur de périphérique lève une
exception, vraisemblablement `GPIOPort.RP2040Pads`.

Essayé sans succès : Renode 1.17.0 et 1.16.1, mode DLL et mode source,
réalignement de la cible `netstandard2.1` sur `net8.0`.

## Recette qui fonctionne, sous Linux x86-64

Le paquet `linux-dotnet` expose ses assemblies dans `renode/bin/`, ce qui
débloque tout. Aucun droit root n'est nécessaire.

```sh
mkdir -p ~/escapement-rp2040 && cd ~/escapement-rp2040

# Renode 1.16.1, version qui tourne sur le .NET de l'hôte
curl -fsSL -O https://github.com/renode/renode/releases/download/v1.16.1/renode-1.16.1.linux-dotnet.tar.gz
mkdir -p renode && tar -xzf renode-1.16.1.linux-dotnet.tar.gz -C renode --strip-components=1

# .NET en local utilisateur
curl -sSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 10.0 --install-dir "$HOME/.dotnet"

# Modèles RP2040
git clone --depth 1 https://github.com/matgla/Renode_RP2040.git
cd Renode_RP2040/emulation
"$HOME/.dotnet/dotnet" build Peripherals.csproj -c Release \
    -p:RenodePath="$HOME/escapement-rp2040/renode/bin"
```

La cible `netstandard2.1` d'origine compile sans modification contre la 1.16.1.

Lancement :

```sh
export PATH="$HOME/.dotnet:$PATH"
~/escapement-rp2040/renode/renode --disable-xwt --console --plain \
  -e 'path add @'"$HOME"'/escapement-rp2040/Renode_RP2040;
      include @boards/initialize_raspberry_pico.resc;
      sysbus LoadELF @firmware.elf;
      start'
```

Validé : le bootrom s'exécute, 6 250 000 instructions en 0,05 s émulée, soit les
125 MHz nominaux du RP2040.

## Répartition du travail

La toolchain `arm-none-eabi-gcc` n'est pas installée sur la machine Linux : on
compile sur le Mac et on copie l'ELF. Les sources et le build restent d'un côté,
l'émulation de l'autre.
