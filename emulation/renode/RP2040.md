# RP2040 emulation (Raspberry Pi Pico)

The RP2040 models do not come from Renode but from the community repository
[`matgla/Renode_RP2040`](https://github.com/matgla/Renode_RP2040), which models
the timer and its four alarms, the clocks (PLL, XOSC, ROSC), the GPIO, the UART,
both cores, the SIO and the PIO.

## It does not work on macOS arm64

The repository is pinned to **Renode 1.16.1**, and its models have to be built
against the Renode assemblies. But the `osx-arm64-portable` package is a
**self-contained** binary: it exposes no referenceable DLL. The “build from
sources” mode fails on its side when the platform is created, right after ROSC
initialisation — a peripheral constructor throws, most likely
`GPIOPort.RP2040Pads`.

Tried without success: Renode 1.17.0 and 1.16.1, DLL mode and source mode,
retargeting `netstandard2.1` to `net8.0`.

## A recipe that works, on Linux x86-64

The `linux-dotnet` package exposes its assemblies under `renode/bin/`, which
unblocks everything. No root privileges are needed.

```sh
mkdir -p ~/escapement-rp2040 && cd ~/escapement-rp2040

# Renode 1.16.1, the version that runs on the .NET of the host
curl -fsSL -O https://github.com/renode/renode/releases/download/v1.16.1/renode-1.16.1.linux-dotnet.tar.gz
mkdir -p renode && tar -xzf renode-1.16.1.linux-dotnet.tar.gz -C renode --strip-components=1

# .NET installed in the user's home
curl -sSL https://dot.net/v1/dotnet-install.sh | bash -s -- --channel 10.0 --install-dir "$HOME/.dotnet"

# RP2040 models
git clone --depth 1 https://github.com/matgla/Renode_RP2040.git
cd Renode_RP2040/emulation
"$HOME/.dotnet/dotnet" build Peripherals.csproj -c Release \
    -p:RenodePath="$HOME/escapement-rp2040/renode/bin"
```

The original `netstandard2.1` target builds unmodified against 1.16.1.

Starting it:

```sh
export PATH="$HOME/.dotnet:$PATH"
~/escapement-rp2040/renode/renode --disable-xwt --console --plain \
  -e 'path add @'"$HOME"'/escapement-rp2040/Renode_RP2040;
      include @boards/initialize_raspberry_pico.resc;
      sysbus LoadELF @firmware.elf;
      start'
```

Verified: the bootrom runs, 6,250,000 instructions in 0.05 emulated seconds,
which is the nominal 125 MHz of the RP2040.

## How the work is split

The `arm-none-eabi-gcc` toolchain is not installed on the Linux machine: the
build happens on the Mac and the ELF is copied over. Sources and build stay on
one side, emulation on the other.
